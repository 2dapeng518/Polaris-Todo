# Polaris 日历套件实施计划

> [!IMPORTANT]
> **实施状态（2026-11-25 更新）**：P0–P3 已全部落地——P0 数据地基（迁移 8 + 备份 v4 + 详情时间编辑，v0.18.0 / `84e4dca`）、P1 多视图骨架（v0.19.0 / `b5aaec9`）、P2 时间轴 + 拖拽 + 区间解析（v0.20.0 / `caac604`）、P3 信息层 + 显示设置 + 搜索筛选（v0.21.0 / `5bc89b8`），门控守卫 `calendarSuiteWorks` 已进 `checks` 表（`eeff4fb`），README 双语同步（`801cf25`）。实现细节以 CLAUDE.md「Calendar view (suite)」为权威，本文保留作决策依据与 P4 待办。**P4（天气/ICS/订阅/打印）尚未实施，待拍板。**

- **日期**：2026-11-25
- **依据**：主流待办应用日历截图对比（月 / 周 / 多周 / 日 / 多日 / 列表 / 看板七视图 + 迷你月历 + 订阅日历 + 显示设置 + 农历/节假日/休班/天气/周数 + 拖拽创建 + 时间轴日程）。当前 Polaris 日历仅为「单月视图 + 任务 chip」，缺口见下。
- **范围**：全量 P0–P4。P4（天气 / 订阅 / ICS / 打印）依赖网络或外部数据，与「本地优先」定位有取舍，**列为可选 / 后置**，不阻塞离线部分。
- **分级原则**：P0 数据模型地基（动 schema，先行）；P1 多视图骨架（纯 UI、ROI 最高，列表/看板不依赖 P0）；P2 时间轴视图 + 交互（依赖 P0）；P3 月格信息层 + 显示设置（离线数据）；P4 在线 / 外部（可选）。
- **规模**：小 ≈ 单文件/数行到半天；中 ≈ 跨文件一到三天；大 ≈ schema/架构级，需设计先行。为相对量级，非承诺工期。
- **执行约束**（CLAUDE.md，逐项适用）：行为改动后 `npm run build && npm run smoke`；主题改动后 `verify:themes`；`lib/dateTime.ts` 改动后 `verify:datetime`；新数据操作四处同步（`shared/types.ts`、`preload/index.ts`、`main/ipc.ts`、`main/db.ts`）+ zod；迁移**只追加新块、永不修改已发布块**；UI 文案双语同进 `src/shared/i18n/`（zh 母本 + en 镜像，漏键 typecheck 报错）；状态文案只陈述静态事实。

## 依赖顺序与里程碑

1. **P0**（0.1→0.2→0.3）：数据模型 + 备份兼容 + 时间编辑入口。
2. **P1**（1.2/1.3 列表/看板可先于 P0；1.1/1.4/1.5 随后）：拿到大部分「看得见」收益。
3. **P2**：时间轴套件（依赖 P0）。
4. **P3**：信息层 + 显示设置。
5. **P4**：在线/外部，单独拍板。

每阶段独立可交付、可验证；建议每阶段一个提交并递增版本号（SemVer）。

## 风险与决策点

- **schema 兼容**：P0 动存储，备份 v1–v4 兼容与冒烟全量回归是硬门槛。
- **节假日数据维护**：休/班依赖国务院年度安排，需内置并逐年更新的数据集。
- **拖拽复杂度**：P2 拖拽交互 + 键盘可达替代，工作量大，可分步。
- **在线 vs 本地优先**：P4 天气/订阅需网络，建议明确「可选」并写入 README 定位，避免定位漂移。
- **测试门控事实**：现有 `calendarWorks`/`matrixWorks` 只进 `POLARIS_SMOKE_RESULT` payload、**不在 `checks` 门控表**（smoke.ts L5452-5622），退出码不由它们决定。**新日历守卫必须加入 `checks` 表**才真正门控；写法照 `calendarWorks`(L2980-3041) 与 `harness/settings.ts` 的 `withSettings` 模式。
