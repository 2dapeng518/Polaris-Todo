# Polaris 开源素材交付清单

> 面向 Polaris v0.2.1（Electron 45 · React 19 · Tailwind v4 · better-sqlite3 · NSIS）。
> 本文与 `docs/asset-atlas/` 的可交互图鉴同源生成，事实字段来自 npm registry、Iconify 上游登记表与实际下载测量。

## 一、结论先行

1. **图标与字体保持现状。** Lucide（ISC）+ Inter / Manrope / Geist Mono / Noto Sans SC（均 OFL-1.1）这套组合已经成立。本轮把 10 个图标库、23 套拉丁字体、3 套中文字体放在一起实测对比，没有找到「换了明显更好」的理由。
2. **真正该补的是合规与体积，不是素材。** 仓库目前没有 NOTICE 文件，而四套 OFL 字体与 Lucide 已经在随 NSIS 安装包再分发；中文字体未子集化，是安装包体积的最大头。这两件事的收益远大于换任何一套素材。
3. **动效自己写就够了。** 本文 10 个动效配方里有 7 个是 0 KB 的纯 CSS/SVG。GSAP / Lottie / Rive 都会带来许可或体积问题，且它们的典型用法（循环播放）直接违反 Polaris「动效只做确认不做装饰」的硬约束。
4. **许可陷阱比想象的多，而且「免费商用」完全不等于开源。** 经 19 个 agent 两轮对抗式核验：MiSans 的 EULA 授权动词只有 `use`、明文禁止再分发，**不能进安装包**；HarmonyOS Sans 反而允许原样嵌入但**禁止任何修改**（子集化这条路封死）且许可可撤销；Remix Icon 的上游登记与 npm 声明冲突；Solar 是 CC-BY-4.0 必须署名；Tabbied 的 MIT 只在子目录、根 LICENSE 是 All rights reserved。详见第六章的推翻记录。

5. **有两类素材压根没有可采纳的开源件。** 装饰性特效与一次性确认动画，在「安静表面 + 禁持续循环」的硬约束下不存在合适的第三方开源素材。本文这两类的配方**全部是自绘或浏览器内置**，零第三方分发物、零许可义务。这是结论，不是遗漏——详见第七章。

## 二、本轮实际做了什么

| 动作 | 结果 |
|---|---|
| 下载拉丁可变字体 woff2 | 23 套，1609 KB（latin 分片实测） |
| 下载中文按需分片 | 2 套 / 38 片，2456 KB，覆盖图鉴全部 332 个试排汉字 |
| 抓取真实图标 SVG | 78 枚，来自 Iconify 官方 API（未经改写） |
| 核验许可证 | 47 条来自 npm registry 机器可读字段 + Iconify 上游登记表 |
| 可运行配方 | 动效 10 个 + 特效 7 个，全部在图鉴页可交互 |
| 建议避开 | 31 条，理由逐条写在清单里 |

## 四、按类别详解

### 4.1 图标：真描边 vs 填充轮廓

这是选型时最容易踩的坑，也是图鉴页可以直接验证的一条：

| 图标库 | 网格 | 描边可调 | 上游许可 | npm 声明 | 图标数 | 判断 |
|---|---|---|---|---|---|---|
| Lucide | 24×24 | ✅ 真描边 | ISC | ISC | 2052 | 保留现状 |
| Tabler Icons | 24×24 | ✅ 真描边 | MIT | MIT | 6545 | 备选 |
| Phosphor | 256×256 | ❌ 填充轮廓 | MIT | MIT | 9072 | 值得考虑 |
| Solar | 24×24 | ✅ 真描边 | CC-BY-4.0 | (未取得) | 9102 | 值得考虑 |
| Iconoir | 24×24 | ✅ 真描边 | MIT | MIT | 1671 | 备选 |
| MingCute | 24×24 | ❌ 填充轮廓 | Apache-2.0 | Apache-2.0 | 4526 | 值得考虑 |
| Heroicons | 24×24 | ✅ 真描边 | MIT | MIT | 1288 | 备选 |
| Remix Icon | 24×24 | ❌ 填充轮廓 | Apache-2.0 | Remix Icon License 1.0 | 3188 | 建议避开 |
| Radix Icons | 15×15 | ❌ 填充轮廓 | MIT | MIT | 332 | 备选 |
| uiw icons | 20×20 | ✅ 真描边 | MIT | MIT | 214 | 建议避开 |

**为什么这条重要**：Polaris 现在用 `.lucide { stroke-width: 1.75 }` 统一描边，勾选与提醒用 2.2。这套做法只对**真描边**的库有效。Phosphor、MingCute、Remix、Radix 的「线性」风格实际是填充轮廓路径，CSS 改 `stroke-width` 对它们完全无效——要改粗细只能换字重变体（例如 Phosphor 的 thin/light/regular/bold）。图鉴页左侧的描边滑块可以现场验证：拖到 2.8，Lucide 与 Solar 明显变粗，Phosphor 纹丝不动。

**Phosphor 的真正价值**不在于替换 Lucide，而在于它的六种字重可以表达状态：未完成用 regular、完成用 fill，状态区分不依赖颜色——这正好呼应 Polaris「不要只用颜色表达状态」的无障碍要求。但代价是引入第二套图标体系，属于 P2。

### 4.3 中文字体：分片效率就是选型依据

中文字体不可能整包进安装包。实测同样覆盖图鉴的 332 个汉字：

| 字体 | 许可 | 命中分片 | 实测体积 | 整包解包 | 是否随预览页分发 |
|---|---|---|---|---|---|
| Noto Sans SC | OFL-1.1 | 19 / 101 | 1063 KB | 4759 KB | 是 |
| Chiron Hei HK 昭源黑体 | OFL-1.1 | 45 / 122 | 10257 KB | 37322 KB | 否（过重） |
| Noto Serif SC | OFL-1.1 | 19 / 101 | 1393 KB | 6254 KB | 是 |

- **Noto Sans SC**：现有中文字体。实测：覆盖图鉴全部 332 个试排汉字只需 19 个分片、约 1.0 MB，是本轮分片效率最好的。
- **Chiron Hei HK 昭源黑体**：实测：同样覆盖 332 字需要 45 个分片、约 10.0 MB —— 是 Noto Sans SC 的 9.6 倍。它的 unicode-range 切分方式与常用字分布不匹配，离线打包代价过高。已测量但不随预览页分发。
- **Noto Serif SC**：衬线中文，仅作对照。Polaris 全站无衬线，引入会破坏一致性。分片效率与 Noto Sans SC 相当（19 片 / 1.4 MB）。

子集化用 `cn-font-split`（Apache-2.0）。**注意 OFL 的 Reserved Font Name 条款**：子集化属于修改，若原字体声明了 RFN，切片产物必须改名。打包前逐个确认。

素材接入方式分三档：

1. **靠 `currentColor` 自动继承**——所有图标。不需要任何颜色覆盖，六套主题天然成立。
2. **靠 CSS 变量映射**——颗粒（`--noise-opacity`）、极光（`--aurora-opacity` + `--accent-rgb` / `--accent-2-rgb` / `--aurora-c-rgb`）、点阵（`--line`）、星点（`mask` + `{{SECRET_l4j4xk2x}}`）。同一份代码，六套主题自动换色。

**陷阱**：`--inner-highlight` 在暗色家族是 4.5% 白，在浅色家族是 **90% 白**。它只能用在半透明玻璃面上；放到饱和 `{{SECRET_l4j4xk2x}}` 填充上，浅色主题会在顶边生成近白描边，看起来像第二层轮廓。图鉴页的特效区有这个缺陷的真实复现。

## 六、对抗式核验：推翻了哪些判断

初版清单交给 19 个 agent 做了两轮独立核验：一轮逐条抓许可证原文与链接，一轮专门找缺口。
下面是被推翻或被补强的结论，**包括推翻本文初版自己的判断**。留着推翻记录比抹掉它有用。

### MiSans 不能进安装包

- **初版**：~~初版写「免费商用但自定义 EULA，本轮排除」——理由含糊，甚至暗示「法律上可以但不建议」。~~
- **核验后**：官方英文 EULA 的授权动词**只有 use**，没有 HarmonyOS 那样的 embed / bundle / redistribute；第 3 项条件明文禁止 "redistribute or sell the font software or any copies thereof"。**结论是硬禁止，不是不建议。**
- **影响**：从「不建议」升级为「不可用」。npm 包 misans@5.0.0 标 Apache-2.0 只覆盖打包代码，救不了字体本体。
- **证据**：核验:cjk-fonts — 官方英文 EULA 原文

### HarmonyOS Sans可以进包，但不能子集化

- **初版**：~~初版把 HarmonyOS Sans 和 MiSans 一起归入「自定义 EULA，本轮排除」。~~
- **核验后**：两者**不一样**：HarmonyOS Sans SC EULA 明确允许未修改副本随软件 embed / bundle / redistribute（NSIS 可以带），但**禁止任何修改**、必须显著署名、许可 **revocable**、违约自动终止。
- **影响**：可以用，但「子集化压体积」这条路对它封死 —— 而中文字体不子集化就是 21.6 MB。许可可撤销这一点对长期发行的产品是额外风险。
- **证据**：核验:cjk-fonts — HarmonyOS Sans EULA 原文

### unDraw 的排除理由说错了

- **初版**：~~初版写「禁止再分发素材本身，与打进 NSIS 安装包存在解释空间」。~~
- **核验后**：原文的「add them in an app」限制是以「插画处于你产品的核心目的」为前提的示例；**普通装饰性内嵌其实落在一般授权范围内**。真正禁止的是把素材打包再分发、做同类竞争服务、以及 AI/ML 用途。
- **影响**：排除结论不变，但准确依据是「自定义 EULA、非 OSI 开源许可」，不是「禁止嵌入你的 App」。把理由说准很重要，否则会误伤其它同类素材。
- **证据**：核验:illustration — unDraw license 原文

### Open Doodles 不是线稿，CC0 依据也不是仓库

- **初版**：~~初版写「CC0，可随包分发」，并暗示是可直接 currentColor 接管的线稿。~~
- **核验后**：拿到作者 about 页原文 CC0 声明 + deed 链接（**无官方 GitHub 仓库 LICENSE**，pablostanley/OpenDoodles 实测 404）。实测 coffee.svg：43,758 B、viewBox 1024×768、**57 个 path、填充剪贴稿**，硬编码 `#000000` 与珊瑚色 `#FF5678`，stroke="none"。
- **影响**：不是 currentColor 线稿，必须改色：`#000000 → currentColor`、`#FF5678 → var(--accent)` 或直接删掉强调块以守「一个 teal」。CC0 结论成立但证据来自作者页而非仓库。
- **证据**：补漏 — 作者 about 页 + coffee.svg 实测结构

### Tabbied 的 MIT 只在子目录

- **初版**：~~初版未收录；常规做法会引用仓库根 LICENSE。~~
- **核验后**：根 LICENSE 是 "Copyright (c) 2020-2026 … **All rights reserved.**" 的专有许可，仅以豁免条款把三个 packages 目录授为 MIT。**真正的 MIT 原文在 packages/tabbied/LICENSE**。
- **影响**：SPDX 仍是 MIT，但范围仅限 packages 子目录。引错文件等于把专有许可当开源用。
- **证据**：核验:effects — 根 LICENSE 与子目录 LICENSE 逐字比对

### 光学补偿系数：×1.11 是错的，实测 ×1.208

- **初版**：~~完整性批判按「几何 bbox 对几何 bbox」算出 ×1.11，并建议 viewBox 收到 24 24 208 208。~~
- **核验后**：补漏进一步指出：**lucide 是真描边，渲染 ink 每边比几何 bbox 多出半个描边**（CSS 1.75 → +0.875）。Inbox 几何 20/24 → ink 21.75/24 = **90.6%**。Phosphor 是填充路径，bbox 即 ink。真实倍率 = 0.90625 / 0.75 = **×1.208**，精确 viewBox 是 `22 22 212 212`（90.57%，误差 0.07%）。
- **影响**：批判自己给的两个建议彼此不一致（×1.11 vs 92.3%），补漏统一到 ink 口径。这是「看起来对但量错了」的典型 —— 混排图标必须按 ink 而不是几何算。
- **证据**：补漏 — 路径 bbox 数值采样

### 描边继承陷阱：注释理由方向反了

- **初版**：~~集成初稿给对勾的 motion.svg 写了 path 级 strokeWidth: 2.6，注释称「必须写 style，否则会被 .task-check .p-icon 盖掉」。~~
- **核验后**：实测该 motion.svg **没有任何 class**，`.lucide` 与 `.p-icon` 都命不中它 —— 没有选择器盖它，注释方向反了。真实后果：2.6 生效 = 1.3px，比现状（2.2 × 12/24 = 1.1px）**粗 18%**，且新令牌管不到全应用最显眼的图标。
- **影响**：正确做法：给 svg 加 className，**删掉 path 的 strokeWidth** 让它继承 svg 的 var(--icon-stroke)。只要 path 自带 stroke-width 就会盖掉继承。
- **证据**：完整性批判 + 补漏 — globals.css:374-381 与 TaskItem.tsx:57-62 实测

### cn-font-split 不是 WASM，也不收 woff2

- **初版**：~~初版集成方案称它是「本地 WASM 工具」，示例未给安装命令与版本。~~
- **核验后**：Node 下走 **koffi 2.10.0 原生 FFI**（dist/auto.mjs 按运行时动态 import ./node/index.mjs），不是纯 WASM。**v7 不支持 woff2 直接输入**，需 ttf/otf。默认产物名 `result.css` 来自 Rust 源码逐字核实。安装：`npm i -D cn-font-split@7.4.3`。
- **影响**：它是 build-time devDependency、不进安装包，所以「运行时零依赖」仍成立 —— 但工具本身需要原生二进制。CFF 子集化产物体积本轮**未实跑**。
- **证据**：补漏 — 发布包 README + 仓库 Rust 源码

### Motion spring() 的真实时长是 400ms

- **初版**：~~调研写「String(spring(0.2, 0)) 得到形如 200ms linear(...) 的字符串」。~~
- **核验后**：用本机已装的 motion 14.12.0 **实跑**，真实输出是 **400ms** linear(0, 0.2175, 0.5207, …)。
- **影响**：照抄会把动效时长写错一倍。Polaris 的 120/200/320ms 三档节奏对不上。
- **证据**：核验:motion — 本机 motion 14.12.0 实跑

## 七、哪些类别根本没找到合适的开源素材

这是结论，不是遗漏。

### 装饰性特效素材

**在设计硬约束下不存在可采纳的第三方开源特效件**

硬约束 4（安静表面、内容面禁毛玻璃）与 5（禁持续循环装饰动画）把市面上绝大多数特效素材直接排除。Pattern Monster 生成物许可存疑且无静态 SVG；Tabbied 的 MIT 只覆盖子目录；shape-dividers 是 CC0 但波浪风格偏营销页。

**替代**：自绘 CSS 渐变（网格/点阵）+ 自绘 feTurbulence 噪点（去饱和）+ Chromium 内置 @starting-style。三件都是自绘或浏览器内置，零第三方分发物、零许可义务。

> 本图鉴「特效」类的 7 个配方**全部是自绘**，没有一件从网络获取的第三方素材。这是结论，不是遗漏。

### 一次性确认动画素材

**不存在合适的第三方开源件**

Lottie / Rive 的典型用法就是循环装饰，与硬约束 5 正面冲突；且 LottieFiles 免费区素材许可逐个不同。GSAP 是自定义 no-charge 许可，非 OSI 开源。

**替代**：已装 motion 14.12.0 的 pathLength 一次性描边 + 纯 CSS keyframes。

> 本图鉴「动效」类的 10 个配方里，7 个是 0 KB 纯 CSS/SVG，其余是已装 motion 的用法。同样没有新增第三方素材。

### 插画 / 空状态图形

**许可最干净的一件也仍有风格张力**

unDraw 自定义 EULA；Storyset 免费需署名且偏营销；Lukasz Adam MIT 同页混称 CC0 与 MIT（法律含义互斥）被判 drop；Open Doodles 是 CC0 但实测是填充剪贴稿 + 硬编码珊瑚色，需改色。

**替代**：不用插画。自绘几何 SVG + 现有四角星做空状态构图 —— 本图鉴的星点亮动效与星点纹理就是成品。

> 若一定要用，Open Doodles coffee.svg 是唯一证据完整、许可干净的选择，已给直链与改色步骤。

### 中文等宽 / 托盘图标

**存在真实语义缺口**

Geist Mono 无 CJK 字形，年/月只能回退 UI 字体；本轮未找到许可干净且 2:1 对齐的中文等宽。托盘语义只有 Phosphor 有（tray / tray-arrow-down / tray-arrow-up），Tabler 与 MingCute 搜索均返回空。

**替代**：等宽：接受年/月回退，或用 Noto Sans SC 单独渲染中文部分。托盘：若要做托盘图标语义，Phosphor 是唯一现成选项。

> 这两条是「现有方案的真实缺口」，不是可以靠换素材解决的问题。

## 八、许可证与合规

Polaris 用 electron-builder 打成 NSIS 安装包对外分发，字体、SVG、JSON 全都构成**再分发**。

### CC0 的证据可能不在仓库里

**Open Doodles 成立，但依据是作者页**（风险：无）

Open Doodles 无官方 GitHub 仓库 LICENSE（pablostanley/OpenDoodles 实测 404）。CC0 依据是作者 about 页原文「without restriction under copyright or database law (CC0 license.)」+ CC0 deed 链接。这比第三方质疑的 Blush 证据更强，但仍不是仓库 LICENSE。

> 可以随包分发、无需署名。把作者 about 页的原文与抓取日期一并存进 licenses/ 作为证据留痕。

### MIT 的范围可能只覆盖子目录

**Tabbied 根 LICENSE 是专有许可**（风险：需署名）

Tabbied 仓库根 LICENSE 写 "All rights reserved."，仅以豁免条款把三个 packages 目录授为 MIT。真正的 MIT 原文在 packages/tabbied/LICENSE。Pattern Monster 的 LICENSE.md 定义句只覆盖 Software，未明示覆盖生成的图案。

> 引用许可必须指到真正授权的那个文件。「仓库有 LICENSE 且写着 MIT」不足以判断素材可用。

### 「免费商用」与包许可的双重陷阱

**npm license 字段救不了素材本体**（风险：存疑）

misans@5.0.0 的 npm license 写 Apache-2.0，但那只是打包代码的许可。同理 @fontpkg/smiley-sans 的 license 指向不存在的 readme、仓库是占位地址；cn-fontsource-smiley-sans-oblique-regular 的 license 字段是 unknown —— 上游得意黑本体确为 OFL-1.1，但那不能替打包产物授权。

> 一律回到素材本体的官方授权原文。第三方打包产物的 license 字段不作为依据；授权不明的包一律不引入对外发布的仓库。

### 自定义 EULA：MiSans 与 HarmonyOS 不是一回事

**MiSans 硬禁止；HarmonyOS 可用但不能改**（风险：自定义协议）

MiSans 官方英文 EULA 的授权动词只有 use，第 3 项明文禁止 "redistribute or sell the font software or any copies thereof" —— 不能进 NSIS 安装包。HarmonyOS Sans 则明确允许未修改副本 embed / bundle / redistribute，但禁止任何修改、必须显著署名、许可 revocable、违约自动终止。

> MiSans 直接排除。HarmonyOS 若要用，必须接受「全量 21.6 MB 不子集化 + 显著署名 + 许可可撤销」三个条件；对长期发行的产品，可撤销许可是实质风险。

### OFL-1.1 字体

**可以随安装包分发**（风险：无）

OFL 允许嵌入软件再分发，条件是随附许可原文与版权声明。唯一红线是「不能单独售卖字体本身」——Polaris 卖的是应用，不触发。

> 把 OFL-1.1.txt 原文放进 licenses/，并在 NOTICE 里列出每套字体的版权行。

### OFL 的 Reserved Font Name

**子集化不改名就不触发**（风险：需署名）

OFL 的 RFN 条款只在「修改字体并继续用原名发布」时触发。pyftsubset / cn-font-split 做的是子集化，属于修改；若字体声明了 RFN，切片后必须改名。

> 切片前先看字体 OFL 头部有没有 "with Reserved Font Name"。Noto 系列没有声明 RFN，Inter / Manrope 需逐个确认；拿不准就给切片产物加前缀（如 PolarisNotoSC）。

### ISC / MIT / Apache-2.0 代码与图标

**可以随安装包分发**（风险：无）

三者都要求保留版权与许可声明。Apache-2.0 额外要求标注修改。minify 后的 bundle 通常靠 NOTICE 集中声明满足。

> NOTICE 集中列出；Apache-2.0 的素材（MingCute、cn-font-split、@paper-design/shaders）若做了修改要写明。

### CC BY 4.0 图案

**可以，但必须署名**（风险：需署名）

CC BY 要求在合理位置标注作者、许可链接、是否修改。打进安装包属于再分发，署名义务成立。

> 署名放 NOTICE + 「设置 → 关于」。不想维护署名就改用自绘图案。

### 自定义 EULA（MiSans / HarmonyOS Sans / 阿里普惠 / GSAP / unDraw）

**逐个确认，本轮不建议引入**（风险：自定义协议）

「免费商用」不是开源许可。npm 包声明的 license 字段可能只覆盖打包代码，不覆盖字体/图形本体——misans@5.0.0 的 npm license 写 Apache-2.0，但小米字体本体走的是自己的授权协议。

> 要用之前必须抓官方授权页原文，确认「可否嵌入软件再分发」「可否子集化改名」。本轮全部排除。

### Remix Icon License 1.0 / Solar

**存疑，本轮不建议引入**（风险：存疑）

@remixicon/react@4.9.0 的 npm license 字段原文是 "Remix Icon License 1.0"，不是常被引用的 Apache-2.0。solar-icons@0.0.15 在 npm 上根本没有 license 字段。

> 两者都需要回到上游仓库确认素材本体的许可，确认前不要进安装包。

## 九、集成方案

### 统一图标适配层

落点：`src/renderer/src/components/Icon.tsx`

现有 12 个组件直接 import lucide-react。加第二套图标库时不要改这 12 个调用点，用一个适配层把「语义名」映射到具体库，切换成本收敛到一个文件。

```tsx
import type { ComponentType, SVGProps } from 'react'
import {
  Bell, CalendarDays, Check, Circle, Flag, Folder,
  Repeat2, Sparkle, Star, Trash2
} from 'lucide-react'

// 语义名 → 组件。换库时只改这张表，调用点不动。
const REGISTRY = {
  bell: Bell,
  calendar: CalendarDays,
  check: Check,
  circle: Circle,
  flag: Flag,
  folder: Folder,
  repeat: Repeat2,
  sparkle: Sparkle,
  star: Star,
  trash: Trash2
} as const satisfies Record<string, ComponentType<SVGProps<SVGSVGElement>>>

export type IconName = keyof typeof REGISTRY

type IconProps = SVGProps<SVGSVGElement> & {
  name: IconName
  size?: number
  // 装饰图标默认从无障碍树里隐藏；承载语义时传 label。
  label?: string
}

export function Icon({ name, size = 16, label, ...rest }: IconProps) {
  const Glyph = REGISTRY[name]
  return (
    <Glyph
      width={size}
      height={size}
      aria-hidden={label ? undefined : true}
      aria-label={label}
      role={label ? 'img' : undefined}
      focusable="false"
      {...rest}
    />
  )
}
```

### 描边继承陷阱（核验实测修正）

落点：`src/renderer/src/components/TaskItem.tsx`

实测：globals.css:374-381 是 .lucide{1.75} / .task-check .lucide{2.2}，TaskItem.tsx:57-62 是 <Check size={12} strokeWidth={2.6}>。CSS 优先级高于呈现属性，真正生效 2.2 × 12/24 = 1.1px。若换成没有 class 的 motion.svg 并在 path 上写 strokeWidth: 2.6，会变成 1.3px（粗 18%），且新令牌管不到它。正确做法：给 svg 加 class，删掉 path 的 strokeWidth 让它继承。

```tsx
{task.completed && (
  <motion.svg
    viewBox="0 0 24 24"
    width={12}
    height={12}
    fill="none"
    aria-hidden="true"
    className="p-icon"
    style={{ stroke: 'var(--check-mark)' }}
  >
    <motion.path
      d="M20 6 9 17l-5-5"
      initial={{ pathLength: reduced ? 1 : 0 }}
      animate={{ pathLength: 1 }}
      transition={{ duration: 0.12, ease: [0.22, 1, 0.36, 1] }}
      style={{ strokeLinecap: 'round', strokeLinejoin: 'round' }}
    />
  </motion.svg>
)}

/* 配套 CSS：stroke-width 设在 svg 上，向 path 继承。
   path 一旦自带 stroke-width（属性或 style）就会盖掉继承。 */
.task-check .p-icon { stroke-width: var(--icon-stroke-strong); }
```

### 混排图标的光学补偿（实测 ink 口径）

落点：`scripts/make-icons.mjs`

lucide 是真描边，渲染 ink 每边比几何 bbox 多半描边（CSS 1.75 → +0.875），Inbox 实际 ink 21.75/24 = 90.6%。Phosphor 是填充路径，bbox 即 ink，tray 只占 75%。按几何算得出的 ×1.11 低估了 lucide，真实倍率是 ×1.208。只改发射的 viewBox，size 与布局盒不变，smoke 高度断言不受影响。

```js
// 逐字形 viewBox 覆盖：把最大 ink 边对齐到 lucide 满幅 ink 90.6%
const GLYPHS = [
  { name: 'Tray',          viewBox: '22 22 212 212' },              // ×1.208
  { name: 'TrayArrowDown', viewBox: '22 22 212 212' },
  { name: 'TrayArrowUp',   viewBox: '22 22 212 212' },
  { name: 'RepeatOnce',    viewBox: '13.23 13.23 229.53 229.53' },  // ×1.115
  { name: 'Circle',        viewBox: '13.24 13.24 229.52 229.52' },
  { name: 'CheckCircle',   viewBox: '13.24 13.24 229.52 229.52' },
  { name: 'Flag',          viewBox: '25.67 21.69 220.66 220.66' }   // ×1.160
]

for (const glyph of GLYPHS) {
  const svg = await readGlyph(glyph.name)
  const viewBox = glyph.viewBox ?? /viewBox="([^"]+)"/.exec(svg)?.[1]
  // 补偿只作用于 .p-icon 发射的 viewBox，lucide 完全不受影响
  emit(glyph.name, svg, viewBox)
}

// 厚度 sanity：tray 壁厚 16 单位 → 16/212×16 = 1.208px
//              lucide 1.75/24×16 = 1.167px（+3.5%，可接受）
```

### 中文子集化（核验修正版）

核验修正三点：① Node 下走 koffi 原生 FFI，不是 WASM；② v7 不支持 woff2 直接输入，需 ttf/otf；③ 默认产物名 result.css 来自 Rust 源码逐字核实，这里显式指定消除歧义。它是 build-time devDependency，不进安装包，运行时零依赖仍成立。CFF 子集化产物体积本轮未实跑。

## 十一、被排除的素材与原因

| 素材 | 原因 |
|---|---|
| Sora Variable | 几何展示体，33 KB。正文小字号偏硬。 |
| Space Grotesk Variable | 展示个性强，但数字与标点造型夸张，不适合待办应用的密集信息。 |
| Roboto Mono Variable | 过于常见，缺乏辨识度，且字形偏旧。 |
| animejs | 轻量时间轴库。Polaris 的动效都是状态驱动，用不上时间轴。 |
| Chiron Hei HK 昭源黑体 | 实测：同样覆盖 332 字需要 45 个分片、约 10.0 MB —— 是 Noto Sans SC 的 9.6 倍。它的 unicode-range 切分方式与常用字分布不匹配，离线打包代价过高。已测量但不随预览页分发。 |

### 找不到合适开源选项的类别

**插画 / 空状态图形**：本轮没有找到既符合「安静的桌面工具」气质、许可又干净到可以随安装包分发的选项。
unDraw 是自定义许可且禁止再分发素材本身；Storyset 免费需署名且风格偏营销；Open Doodles 是 CC0 许可最干净，但手绘涂鸦风格与 Polaris 的精确感冲突。

**替代建议**：不用插画。用几何 SVG 自绘 + 现有的四角星标记做空状态构图——图鉴页的星点亮动效与星点纹理就是这个方向的成品，0 KB、无许可负担、六套主题自动适配。

**循环动画素材（Lottie 免费区）**：播放器 `lottie-web` 本身是 MIT，但素材许可逐个不同，且免费区绝大多数是循环动画，直接违反设计约束。替代建议就是本文第 4.4 节的 10 个一次性配方。

## 十二、未验证 / 存疑项

诚实列出本轮没能确认的：

- **Haikei**：生成器免费，但产出物的许可条款本轮未抓到原文，标记为未验证，不要当作 CC0 使用。
- **Hero Patterns**： commonly 引用为 CC BY 4.0（图案）/ MIT（站点代码），本轮未逐条抓取原文；若要用，署名义务按 CC BY 处理。
- **部分素材站点不可达**：phosphoricons.com、tabler.io/icons 等在抓取时连接失败，许可证结论改由 GitHub 仓库与 Iconify 上游登记表交叉印证，不影响许可结论，但官网预览链接可能需要在你的网络环境下重试。
- **Iconify API 限流**：抓取过程中多次 429，Radix 的部分语义与 Tabler 的计数未二次复核。
- **中文分片覆盖范围**：只覆盖图鉴用到的 332 个汉字，超出范围回退系统字体。这是 unicode-range 的正常行为，不是缺陷，但生产环境要按实际文案重新切片。
