## 补 1｜对勾改造：描边回到 1.1px，并真正纳入 `--icon-stroke`（缺口 1）

**实测复核（与批判一致）**：`globals.css:374-381` 当前只有 `.lucide { stroke-width: 1.75 }` 与 `.task-check .lucide, .reminder-primary .lucide { stroke-width: 2.2 }`；`TaskItem.tsx:46` 是 `button.task-check`，`57-62` 是 `<Check size={12} strokeWidth={2.6}>`。CSS 优先级高于呈现属性，真正生效 **2.2 用户单位 × 12/24 = 1.1px**。

**错误根源确认**：原 6.4 的 `motion.svg` 没有任何 class，`.lucide` / `.p-icon` 都命不中它 → 写在 path `style` 里的 `strokeWidth: 2.6` 直接生效 = **1.3px（比现状粗 18%）**，且新令牌 `--icon-stroke` 管不到全应用最显眼的这个图标。原注释「strokeWidth 必须写 style，否则会被 `.task-check .p-icon` 盖掉」**方向反了**：没有 class 时根本没有选择器盖它。

**修正写法**（替换 `TaskItem.tsx:51-64`；顶部 `import { motion, useReducedMotion } from 'motion/react'`，组件内 `const reduced = useReducedMotion()`）：

```tsx
{task.completed && (
  <motion.svg
    viewBox="0 0 24 24"
    width={12}
    height={12}
    fill="none"
    aria-hidden="true"
    className="p-icon"                 /* 命中 6.3 的 .task-check .p-icon → --icon-stroke: 2.2 */
    style={{ stroke: 'var(--check-mark)' }}
  >
    <motion.path
      d="M20 6 9 17l-5-5"
      initial={{ pathLength: reduced ? 1 : 0 }}
      animate={{ pathLength: 1 }}
      transition={{ duration: 0.12, ease: [0.22, 1, 0.36, 1] }}
      style={{ strokeLinecap: 'round', strokeLinejoin: 'round' }}  /* 不写 strokeWidth */
    />
  </motion.svg>
)}
```

**关键继承陷阱（必须照做）**：6.3 的 `stroke-width: var(--icon-stroke)` 设在 **svg** 上、向 path **继承**。只要 path 自带 `stroke-width`（属性或 style）就会盖掉继承——所以**必须删掉 path 的 `strokeWidth`**，让它继承 svg 的 2.2。结果 2.2 × 12/24 = **1.1px，与现状逐像素一致**，且 `--icon-stroke` 现在管得到它，6.3「统一描边走令牌」不再自相矛盾。`--check-mark` 颜色与 reduced-motion 终态渲染均保留。

**验证**：`npm run build && npm run smoke`（100/125/150/200% 高度断言）＋ `POLARIS_SHOT=detail npx electron . --user-data-dir=<临时目录>` 改前改后并排（临时 profile 隔离，避免改真实主题）。

### 2.1 `cn-font-split`：安装命令 + API + 产物名（源码核实，未实跑）

- **选项名核实**：发布包 [README](https://unpkg.com/cn-font-split@7.4.3/README.md) 的 JS 示例为 `import { fontSplit } from 'cn-font-split'; await fontSplit({ input, outDir, … })`，含 `input / outDir / css / chunkSize`，`css` 子字段含 `fontFamily / fontWeight / fontDisplay`。原清单脚本的 `{input, outDir, css:{fontFamily,fontWeight,fontDisplay}, chunkSize}` **全部是合法 camelCase 选项**。proto 定义（[crates/proto/src/index.proto](https://raw.githubusercontent.com/KonghaYao/cn-font-split/release/crates/proto/src/index.proto)）逐字对应 `input / out_dir / css / chunk_size` 与 `font_family / font_weight / font_display`。
- **`result.css` 产物名核实（权威）**：Rust 核心 `src/link_subset/mod.rs` 逐字 `let css_file_name = css.file_name.unwrap_or("result.css".to_string()); output_file(ctx, &css_file_name, …)`（[gh code search 命中](https://github.com/KonghaYao/cn-font-split)）。**默认输出就是 `result.css`**，可用 `css.fileName` 覆盖；原清单 `import './assets/fonts/glow-sans/result.css'` 正确。
- **两条纠正**：① v7 **不支持直接 woff2 输入**（README 迁移说明：先转 ttf）；Glow Sans 是 **OTF**，符合输入要求（OTF/CFF 子集化未实跑确认）。② Node 下走 **Rust FFI（koffi 2.10.0 原生绑定）**，不是「纯 WASM」——`dist/auto.mjs` 实测按运行时动态 import `./node/index.mjs`（另有 bun/deno/wasm-edge 入口）。它是 **build-time devDependency、不进安装包**，故「运行时零依赖」仍成立，但工具本身需要原生二进制。
- **未实跑标注**：本环境禁止安装执行外部包，`fontSplit` 未实际运行；以上 API/产物名来自发布包 README 与仓库源码，**CFF 子集化产物体积未实测**。

**修正后的 `scripts/split-fonts.mjs`**（显式 `fileName` 消除默认名歧义）：

```js
// 构建期一次性运行，产物入库。cn-font-split@7.4.3 是 Apache-2.0 的本地工具
// （Node 下走 koffi 原生 FFI），devDependency，运行时零依赖。用法：node scripts/split-fonts.mjs
import { readFile } from 'node:fs/promises'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'
import { fontSplit } from 'cn-font-split'

const root = join(dirname(fileURLToPath(import.meta.url)), '..')
const src = join(root, 'scripts/vendor/glow-sans/GlowSansSC-Normal-Book.otf') // 需先按 2.2 放置

await fontSplit({
  input: new Uint8Array(await readFile(src)), // v7 收 ttf/otf，不收 woff2
  outDir: join(root, 'src/renderer/src/assets/fonts/glow-sans'),
  css: {
    fontFamily: 'Glow Sans',
    fontWeight: '400 700',
    fontDisplay: 'swap',
    fileName: 'result.css' // 显式指定，保证 main.tsx 的 import 路径确定
  },
  chunkSize: 70 * 1024
})
```

## 补 5｜vendored 字形光学补偿：实测系数 + 只作用于 `.p-icon`（缺口 5）

**实测 bbox（数值采样，256/24 网格）：**

| 字形 | 内容 bbox | 内容占比 |
|---|---|---|
| Phosphor Tray / TrayArrowDown / TrayArrowUp | 32,32 → 224,224（192×192） | 75.0% |
| Phosphor RepeatOnce | 24,32 → 232,224（208×192） | 宽 81.3% |
| Phosphor Circle / CheckCircle(fill) | 24,24 → 232,232（208×208） | 81.25% |
| Phosphor Flag(fill) | 40,32 → 232,232（192×200，中心 136,132） | 高 78.1% |
| lucide Inbox / Circle / CircleCheck / Repeat2 | 几何宽 20/24 | 几何 83.3% |

**关键纠正（比批判更进一步）**：lucide 是**真描边**，渲染 ink 比几何 bbox 每边多出半个描边（应用 CSS 1.75 → +0.875）。Inbox 几何 x2..22 → **ink x1.125..22.875 = 21.75/24 = 90.6%**。Phosphor 是填充路径，bbox 即 ink。所以：

- 批判的「×1.11」是**几何对几何**口径，低估了 lucide 的实际 ink；tray 对 Inbox 的**真实光学倍率 = 0.90625 / 0.75 = ×1.208**。
- 批判的 viewBox `24 24 208 208` 给出 192/208 = **92.3%**，略**超** Inbox 的 90.6%（+1.9%）；精确窗口 = 192/0.90625 = 211.86 → **`22 22 212 212`**（90.57%，误差 0.07%）。批判的两个建议彼此不一致，这里统一到 **ink 口径**。

**统一规则**：把每个 vendored 字形的**最大 ink 边**对齐到 lucide 满幅 ink **90.6%**（参照 Inbox / Circle）。逐字形 viewBox 覆盖（实测计算，只改发射的 viewBox，`size` 与布局盒不变）：

| 字形 | 对齐后 viewBox | 等效倍率 |
|---|---|---|
| Tray / TrayArrowDown / TrayArrowUp | `22 22 212 212` | ×1.208 |
| RepeatOnce | `13.23 13.23 229.53 229.53` | ×1.115 |
| CircleGlyph / CheckCircleGlyph | `13.24 13.24 229.52 229.52` | ×1.115 |
| FlagGlyph | `25.67 21.69 220.66 220.66` | ×1.160 |

**接入（`scripts/make-icons.mjs` 两处小改）**：`GLYPHS` 每项加 `viewBox` 字段（上表值），循环里把 `const viewBox = …` 改为 `const viewBox = glyph.viewBox ?? /viewBox="([^"]+)"/.exec(svg)?.[1]`。**补偿只作用于 `.p-icon` 发射的 viewBox，lucide 完全不受影响**；布局盒不变 → smoke 高度断言不受影响，但图标视觉变大，需目视核对。

**厚度 sanity**：tray 壁厚 16 单位 → 16px 下 16/212×16 = **1.208px**，lucide 1.75/24×16 = **1.167px**（+3.5%，可接受）；对齐 ink 的同时描边重量也接近。

**验证**：`POLARIS_SHOT=themes npx electron . --user-data-dir=<临时目录>` 六套逐一截图，tray 与相邻 lucide 并排放大；必要时用路径 bbox 量化（本轮已用数值采样脚本测出上表，非目测）。
