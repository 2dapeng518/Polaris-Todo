给 Polaris 的
素材图鉴

每一条素材都真的抓下来了：字体是从 jsDelivr 下载的 woff2，图标是 Iconify 官方 API 返回的原始 SVG， 许可证来自 npm registry 与上游登记表，不是凭记忆写的。左侧控制台可以实时改参数， 六套主题随时切换，看看它们在你的画布上到底长什么样。

结论先行

    01 · 图标

    描边一致性对比台

    同一组语义、同一个尺寸、同一套主题色，横向比十个图标库。 左侧控制台的「描边粗细」只对真描边的库生效——Phosphor、MingCute、Remix 的线性风格是填充轮廓， 拖动滑块它们纹丝不动，这本身就是选型时最容易踩的坑。点任意图标看源码与许可。

    02 · 字体

    真字体试排台

    下面每一套字体都是已经下载到本地的 woff2，不是 CDN 占位。 改字号、字重、字样内容，看小字号屏显、等宽数字与中文混排。字节数是实际下载大小（latin 分片）。

    02b · 中文

    中文字体：按需分片的真实代价

    中文字体不可能整包塞进安装包。下面三套都真的按 unicode-range 下载了分片， 覆盖图鉴里全部试排汉字。分片数与字节数是实测值——这个差距就是选型依据。

    03 · 动效

    可重播的动效实验台

    Polaris 的规矩是「动效只做确认，不做装饰」，所以这里没有一个循环播放的动画—— 每个都要你点「重播」才动。这也正是它们该有的样子：绑定在真实交互上。 打开左侧「减弱动效」，全部立即渲染终态。

    动效：开
    04 · 特效

    零运行时的纹理与光

    全部是 CSS 与内联 SVG，没有第三方运行时、没有持续动画。 颜色一律经由令牌，所以同一份代码在六套主题下自动换色——包括那个内高光陷阱的真实复现。

    06 · 对抗式核验

    核验推翻了哪些判断

    初版清单交给 19 个 agent 做了两轮独立核验：一轮逐条抓许可证原文与链接，一轮专门找缺口。 下面每一条都是被推翻或被补强的结论，包括推翻我自己的。留着推翻记录比抹掉它有用。

    06b · 诚实结论

    哪些类别根本没找到合适的开源素材

    这是结论，不是遗漏。有两类素材在 Polaris 的设计硬约束下压根不存在可采纳的第三方开源件—— 说清楚比硬凑几件更有用。

    07 · 许可证与合规

    打进 NSIS 安装包意味着什么

    Polaris 用 electron-builder 打成安装包对外分发，字体、SVG、JSON 全都构成再分发。 下面逐条说明哪些义务被触发、怎么落地。左侧「生成 NOTICE」会按当前筛选结果产出可直接用的声明文件。

    08 · 集成方案

    落到这个仓库的真实文件

    代码遵守仓库风格：2 空格缩进、单引号、无分号、TypeScript。文件路径都是仓库里真实存在或建议新增的位置。

    数据来源

    本页所有事实字段由 docs/asset-atlas/tools/ 下的抓取脚本生成： 字体来自 jsDelivr 的 @fontsource 包，许可证与版本来自 npm registry，图标 SVG 与集合许可来自 Iconify 官方 API 与上游 icon-sets 登记表。 抓取结果原始 JSON 存放在 data/，可复现。

    字体文件仅供本页预览，不建议提交进 git；应用运行时的正确引入方式是 npm 的 @fontsource-variable 包。
