# Polaris 改进计划清单

- **依据**：`docs/功能盘点与同类产品对比报告-2026-11-15.md`（232 项功能盘点、61 条待办核对、同类产品对比、附录 A 文档漂移清单），证据行号均已在报告中核实。
- **分级原则**：P0 不解决不宜对外分发；P1 数据/逻辑已就绪、补 UI 与闭环，ROI 最高；P2 是与同类产品对标的**新功能面**，需产品拍板后启动；P3 低成本工程与文档卫生，可穿插做；P4 是素材清单遗留，研究多已有结论。
- **规模**：小 ≈ 单文件/数行到半天；中 ≈ 跨文件一到三天；大 ≈  schema/架构级，需设计先行。为相对量级，非承诺工期。
- **执行约束**（CLAUDE.md，逐项适用）：行为改动后 `npm run build && npm run smoke`；主题改动后 `verify:themes`；`lib/dateTime.ts` 改动后 `verify:datetime`；新数据操作四处同步（shared/types.ts、preload、main/ipc.ts、main/db.ts）+ zod；迁移只追加不改已发布块；UI 走既定设计流程（UI UX Pro Max → hue → web-design-guidelines → unslop）；状态文案只陈述静态事实；每个含行为变化的提交同步递增版本号（SemVer，package.json + lockfile）。
